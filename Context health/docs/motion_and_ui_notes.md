# Context Health 모션·UI 작업 노트

2026년 10월 초 홈·분석 개편 작업에서 정한 것들을 모았다.
새 화면이나 모션을 만들 때 여기 값을 먼저 쓰고, 바꿀 때는 이 문서도 같이 고친다.

---

## 1. 모션을 대하는 기준

- **시키지 않아도 모션을 같이 설계한다.** 새 요소가 나타나거나, 상태가 바뀌거나, 화면이 전환되면 "뚝" 바뀌지 않게 한다.
- **토스를 기준으로 한다.** 디자인 판단은 `Toss mobile md/TOSS_MOBILE.md`를 따른다.
- **탄성은 살짝만.** 지나쳤다 돌아오는 폭은 작게, 시간은 0.5초 안쪽으로 잡는다.
- **손가락을 따라가는 모션은 시간이 아니라 거리로 그린다.** 당기는 동안은 당긴 거리가 곧 모양이고, 손을 놓은 뒤에만 시간으로 움직인다.
- **한번 시작한 모션은 끝까지 간다.** 중간에 끊기면 산만해 보인다 (카드 눌림 색이 대표 사례).
- **되돌아오는 길도 같은 모양으로.** 나갈 때 리퀴드였으면 돌아올 때도 리퀴드다.
- **움직임 줄이기 설정(`prefers-reduced-motion`)에서는 전부 끈다.** 새 모션을 넣으면 `src/index.css`의 해당 블록에도 추가한다.

## 2. 모션별 값

### 카드 눌림 — `src/components/common/PressCard.jsx`

| 항목 | 값 |
|---|---|
| 눌림 색 | `#e9ecef` |
| 크기 | 0.98배, 누르는 동안 유지 |
| 구조 | 흰 카드 안쪽 4px에 따로 있는 영역(모서리 16)에만 색이 찬다 |
| 색이 퍼지는 방식 | 가운데에서 바깥으로. 0→70%는 35ms(눈에 안 보일 만큼), 70→100%는 200ms |
| 줄어드는 시간 | 90ms |
| 돌아오는 시간 | 300ms, `cubic-bezier(0.3, 1.35, 0.5, 1)` |
| 터치 대기 | 40ms. 그 전에 손이 6px 넘게 움직이면 스크롤로 보고 아무 효과도 내지 않는다 |
| 짧게 톡 눌렀을 때 | 남은 색을 1.6배속으로 끝까지 채운 뒤 뺀다 |
| 꾹 누르기 | 1초 → 더보기 메뉴 |

- 카드 안의 `button, a, input, textarea, [data-no-press]`를 누를 때는 카드 효과를 내지 않는다.
- 글자 선택·복사 메뉴는 끈다. 켜져 있으면 폰이 터치를 취소해서 눌림이 풀린다.
- 눌리는 영역 안쪽에 불투명한 배경을 두면 퍼지는 색이 가려진다.
- 터치 대기 40ms는 "스크롤 중 눌림 방지"와 맞바꾼 값이다. 0으로 내리면 스크롤할 때 카드가 눌린다.

### 탭 막대 — `src/components/common/MainTab.jsx`

- 막대는 하나만 두고 선택된 탭으로 미끄러진다: 460ms, `cubic-bezier(0.3, 1.3, 0.45, 1)`.
- 글자는 회색 글자와 보라 굵은 글자 두 겹을 겹쳐 투명도만 바꾼다(220ms). 굵기가 뚝 바뀌지 않는다.

### 하단 탭 화면 전환 — `.tab-panel` (`src/index.css`)

- 토스식: 쉬는 탭은 화면 폭의 5%만 비켜 서서 투명하게 기다린다. 누르면 떠나는 화면은 0.04초에 사라지고, 들어오는 화면은 이미 95% 위치에서 보인 채 남은 5%만 450ms `cubic-bezier(0.25, 1, 0.5, 1)`로 들어와 멈춘다.
- 거쳐 간 안: 화면 전체(100%)를 0.15초·0.05초에 95%까지 미는 스프링, 거기에 0.02초 투명도 교차. 둘 다 두 화면이 나란히 밀려가는 게 한순간 보여 뻑뻑했다.
- 예전 값 420ms `ease-in-out`은 출발이 느려서 둔하게 느껴졌다.

### 목록 카드 등장 — `.stagger-in`

- 한 줄씩 차례로 20px 아래에서 올라온다: 480ms, `cubic-bezier(0.2, 0.8, 0.3, 1)`, 줄마다 65ms 간격.
- 앞쪽 9줄에만 건다. 그 뒤는 모션 없이 나타난다.
- 2칸짜리 타일은 한 줄이 같이 올라온다.
- 탭이나 날짜를 바꾸면 다시 재생한다.

### 그래프 등장 — 분석 탭, 홈 요약

| 종류 | 방식 | 클래스 |
|---|---|---|
| 선 | 왼쪽에서 오른쪽으로 그려진다 (900ms) | `chart-draw` + `pathLength="1"` |
| 면이 있는 차트 | 왼쪽부터 드러난다 (1000ms) | `chart-wipe` |
| 세로 막대 | 왼쪽부터 하나씩 올라온다 (520ms, 40~45ms 간격) | `chart-bar` + `--d` |
| 진행 바 | 왼쪽에서 늘어난다 (750ms) | `chart-grow-x` |
| 끝점 원 | 마지막에 톡 나타난다 | `chart-dot`, `chart-dot-in` |

그래프 성격을 가진 것은 전부 등장 모션이 있어야 한다.

### 홈 당겨서 새로고침 (리퀴드) — `src/components/home/HomeHeader.jsx`

- 시트를 당기면 탭과 시트를 잇는 목이 생기고, 당길수록 가늘어진다.
- 40px(`NECK_BREAK`)에서 끊어진다. 탭은 알약 모양으로 튕겨 올라가고, 시트 쪽 방울은 가라앉는다.
- 52px 넘게 당기고 놓으면 새로고침. 새로고침하는 동안 틈은 56px.
- 손을 놓으면 당긴 거리 자체가 420ms에 걸쳐 0으로 돌아간다. 틈·목·탭 모서리가 같은 값을 따라가서 다시 붙는 과정이 보인다.
- 새로고침 아이콘은 목이 끊어진 뒤부터 나타난다.

### 홈 상단 스크롤

- 화면 전체가 하나의 스크롤이다.
- 날짜 줄은 맨 위에 붙고, 탭은 그 아래까지 올라와 붙는다.
- 주간 띠는 제자리에 있고, 탭과 흰 시트가 그 위로 올라와 가린다.
- 주간 띠는 옆으로 밀면 한 주씩 넘어간다 (지난 26주, 더 옛날 날짜를 고르면 늘어남).

- 화면은 검정 60%로 어두워진다.
- 운동·식단 두 원이 가운데 버튼 자리에서 튀어나온다: 460ms, `cubic-bezier(0.25, 1.45, 0.45, 1)`, 식단은 50ms 늦게.

## 3. 겪은 함정 (다시 밟지 않기)

### 움직임이 끝난 뒤 `transform`을 남기지 않는다
조상 요소에 `transform`이 남아 있으면 그 안의 `position: fixed` 요소가 화면이 아니라 그 조상을 기준으로 잡힌다. 더보기 메뉴의 바깥 닫기 영역이 카드 크기로 줄어들었던 원인이다.
- CSS 애니메이션은 `backwards`만 쓴다 (`both`, `forwards` 금지).
- Web Animations는 원래 크기로 돌아갈 때 `fill: 'none'`.
- 바깥을 눌러 닫는 것은 고정 배경 대신 `src/lib/useDismiss.js`를 쓴다.

### 스크롤 영역을 둥글게 자르지 않는다
`overflow` 스크롤 요소에 `border-radius`를 주면 일부 폰에서 모서리가 검게 깜빡인다. 시트는 네모로 두고, 모서리 자리에 바탕색 조각(`SheetCorners`)을 덮어 둥글게 보이게 한다.

### 소수점 높이가 만나는 경계에는 실선이 비친다
당기는 틈처럼 높이가 소수점인 요소 옆에서는 뒤 배경색이 실선처럼 보인다. 옆 요소를 1px 겹친다.

### 터치에서는 손을 뗀 뒤에도 이벤트가 따라온다
`pointerup` 다음에 `pointerleave`가 온다. 이걸 취소로 받으면 방금 시작한 효과가 바로 끊긴다. 누르는 중일 때만 취소로 처리한다.

### 당기다 만 상태를 남기지 않는다
당기다가 손을 다시 올리거나 스크롤로 넘어가면 당긴 거리를 0으로 되돌린다. 손을 뗄 때도 한 번 더 되돌린다.

### 옆으로 미는 영역과 당겨서 새로고침이 싸운다
옆으로 스크롤되는 영역에는 `data-no-pull`을 붙여 새로고침 손짓으로 받지 않게 한다.

### 입력 중에 화면이 바뀌면 키보드가 닫힌다
입력창이 포커스를 받았다는 신호(`onFocus`)가 끊기면, 내용에 따라 보기 화면으로 바뀌면서 키보드가 닫힌다. 입력 컴포넌트를 감쌀 때 `onFocus`를 꼭 넘긴다.

### 설치한 앱(안드로이드)의 화면 맨 아래 줄 색은 manifest의 background_color가 정한다
홈 화면 아이콘으로 연 앱에서 맨 위 시계 줄은 `meta theme-color`가, 맨 아래 제스처 줄은 `vite.config.js` manifest의 `background_color`가 칠한다. 크롬 탭에서는 아래 줄을 크롬이 칠해서 이 차이가 안 보인다.
2026-10-06에 `background_color`를 연보라로 바꿨다가, 설치된 앱이 며칠 뒤 그 설정을 받아가면서 하단 네비 아래에 보라 띠가 생겼다. 지금은 `#ffffff`. 바꾸면 설치된 앱에는 크롬이 업데이트할 때(하루 이틀) 또는 다시 설치할 때 반영된다.

### 막기만 하고 이유를 말하지 않으면 고장처럼 보인다
미래 날짜처럼 못 가는 곳을 막을 때는 알림으로 이유를 알려준다.

## 4. 성능

- **긴 목록은 한꺼번에 그리지 않는다.** 홈은 처음 6장, 목록 끝이 가까워질 때마다 12장씩 이어서 그린다. "잠시 뒤에 나머지 전부"는 그 순간 버벅인다.
- **등장 모션은 화면에 보이는 앞쪽에만 건다.**
- **`will-change`를 미리 걸어두지 않는다.** 카드 수만큼 레이어가 생긴다.
- **매번 다시 계산하지 않는다.** 날짜별 묶음, 요약, 주간 띠처럼 무거운 것은 필요할 때만 다시 계산한다.

## 6. 확인하는 방법

- **미리보기**: `preview/home.html`, `preview/analysis.html`, `preview/diet.html`(`?meal=lunch`, `?empty`, `?open=menu|more|plus|foods|search|manual|edit|focus`, `?pick=2`). 더미 데이터로 그리고, 주소 뒤 값으로 상태를 바꾼다 (`?tab=diet`, `?empty`, `?scroll=120`, `?pull=26`, `?memo`).
- **정지 화면으로 볼 수 있는 것**: 배치, 색, 당긴 거리별 모양.
- **폰에서만 볼 수 있는 것**: 탄성의 느낌, 터치 반응, 키보드 동작. 확인하지 못했으면 못 했다고 말한다.
- **측정 주의**: 화면에 안 보이는 탭이나 자동 브라우저에서는 타이머와 애니메이션이 멈춰 있어, 시간을 재면 엉뚱한 값이 나온다.
- **배포 후**: 새 버전은 새로고침을 두 번 해야 보인다.

## 7. 일하는 순서

1. 큰 UI 변경은 시안부터 본다. 더미 데이터로 그림을 뽑아 방향을 정한 뒤 만든다.
2. 피그마 디자인이 있으면 수치·색·그라데이션을 그대로 옮긴다. 디자인에 없는 부분(빈 상태, 모션)은 직접 정하고, 무엇을 정했는지 알린다.
3. 빈 상태를 먼저 나열한다: 기록이 하나도 없음, 오늘만 없음, 지난 날짜에 없음, 불러오는 중, 설정이 안 됨.
4. 미리보기로 확인하고 배포한다. 로그인·인증을 건드렸으면 실제 브라우저에서 탭 두 개로 확인한다.
5. 커밋은 요청이 있을 때 한다.
