# 실제 앱 관찰 기록

2026-09-07 16:06–16:22 KST, Chrome, https://context-health-3eb84.web.app/.
기존 사용자 탭은 보존하고 별도 QA 탭 사용. 계정 식별자와 실제 기록 본문은 문서에서 제외.
아래는 도구 결과를 옮긴 관찰 기록이며 자동 원본 로그가 아님. HTTP/함수 실험은 별도 JSON 원본 참조.

## B01 로그인

새 격리 브라우저 390×844에서 로그인 화면 표시, Apple/Google/카카오/네이버 버튼 4개. `live-login-390.png` 실제 캡처를 열어 확인. 가로 잘림 없음.
기존 로그인 세션에서는 홈의 운동 및 식단 기록 조회 성공. 새로운 OAuth 승인/계정 생성은 실행하지 않음.

## B02 브라우저 뒤로가기

운동 편집 화면의 첫 `운동의 무게와 세트수 등 편하게 적어주세요` 입력칸을 `QA_UNSAVED_20260907 60kg 10회`로 변경. 저장 클릭 없이 브라우저 back 실행.
도구 결과: `{exitDialog: 0, editorCount: 0}`. 편집 화면이 닫힘. 앱 코드의 popstate는 화면을 바로 교체. DB 쓰기 없음.
원래 필드에는 기존 운동 내용이 표시되어 있었으므로 '순수 빈 신규 메모'로 기술하지 않음. 임시 입력은 저장하지 않음.

## B03 식단 기본 레이아웃

새 식단 화면의 제목과 저장 버튼 DOM 좌표 검사. 입력값/기록 저장 없음.

| CSS 뷰포트 | 제목 x | 저장 버튼 left–right | 저장 버튼 top–bottom | 조상 가로 스크롤 |
|---|---:|---|---|---|
| 320×568 | 56 | 20–300 | 472–528 | 없음 |
| 390×844 | 56 | 20–370 | 748–804 | 없음 |
| 667×375 | 174.5 | 138.5–528.5 | 279–335 | 없음 |

해당 상태에서 제목·저장 버튼은 화면 안. 전체 모바일 QA 통과를 의미하지 않음. iOS/Android 실제 키보드, 안전영역, 설치 PWA 미검증.
한 차례 초기 리사이즈·접근성 클릭 뒤 메인 컨테이너 scrollLeft=149.5, 제목 x=-93.5를 관찰했지만 새로고침 후 재현되지 않음. 뷰포트 도구의 캡처 배율 이상도 관찰. 확정 UI 버그로 분류하지 않고 V-MOBILE에 기록.

## B04 음수 영양값

`내 음식 등록` 열기 → 음식명 `QA 임시 음식` → kcal `100` → 탄수화물 `-10`.
도구 결과 `{saveEnabledWithNegativeCarbs: true}`. 저장 버튼을 누르지 않고 배경 클릭으로 닫음. 모달 개수 0 확인.

## B05 분석 전 식단 저장 가능

새 식단 아침 입력칸에 `QA 바나나 하나` 입력. AI 분석 실행 전 `{saveEnabledBeforeAnalysis: true}`.
실제 저장은 하지 않음. 동일 저장 함수의 격리 실행에서 원문이 payload에서 사라지는 사실 확인(QA-07).
앱 헤더 뒤로가기 확인 모달에 대한 최종 확인은 후속 사용자 메시지로 임시 탭이 종료되어 미완료. 이를 PASS로 집계하지 않음.

## B06 접근성 트리

홈·상세 화면의 DOM/AX 스냅샷에 화면 밖 AI 코치, 마이페이지 및 `저장되었습니다`가 동시에 존재. Toast는 show=false 때 opacity만 0, aria-hidden/inert 없음. 실제 스크린리더 낭독/키보드 순서 시험은 미실행.

## 종료

명시적 뷰포트 override는 reset 완료. 운영 기록 저장·삭제·탈퇴·AI 유료 요청 실행 없음. 임시 입력만 사용. QA 전용 탭은 후속 메시지 시 자동 종료됨.
