## 판단

| 항목 | 수용 여부와 정확한 표현 |
|---|---|
| QA-02 계정별 캐시 분리 | 수용. `55510a3`의 로그아웃 삭제 목록과 현재 코드를 대조하여 같은 누락 위험이 확인됐다. 특정 키 세 개만 추가하는 방식보다 UID별 저장·전환 시 메모리 초기화를 우선한다. 기존 전역 캐시는 소유자를 입증하지 못하면 현재 로그인 사용자에게 자동 귀속시키지 않는다. |
| QA-06 AI 덮어쓰기 | 결함·고착 회귀 검사 필요성 수용. 단, ‘AI 처리 중 재저장이면 반드시 모든 수정 소실’은 과도하다. A의 sections 쓰기 전에 B를 저장하고 A의 오래된 쓰기가 성공하면 sections가 덮어써지는 조건이 기존 probe로 재현됐다. A가 sections를 이미 쓴 뒤 한줄평만 기다리는 구간에서는 B의 sections가 유지되고 aiComment/aiStatus 등이 오래된 작업에 의해 바뀔 수 있다. 쓰기 실패·탭 종료도 구분해야 한다. 경쟁 상태라는 분류 자체가 틀린 것은 아니다. 원문 필드까지 전부 삭제됐다고 주장하지 않는다. |
| QA-03 식단 가드 재사용 | 참고 패턴으로만 수용. 식단은 saving/disabled가 있지만 handler 진입의 동기 guard나 서버 중복 방지 키가 없다. 보통의 반복 클릭 방어와 다중 호출·탭·재시도 안전성은 다르다. 식단 중복 재현을 새 확정 버그로 추가하지도, 식단이 완전히 안전하다고 판정하지도 않는다. |
| QA-08 탈퇴 실패 | 수용. 클라이언트는 실패 응답에서 로컬/서버 선삭제를 하지 않는다. 기존 운영 404 증거의 경로에 한해 반쯤 삭제되었다고 볼 근거 없음. 향후 배포될 함수의 부분 삭제 위험과 구분한다. |
| V-DELETE | 부분 batch 성공 후 실패 및 Auth 삭제 실패를 별도 시험한다. 현 클라이언트 alert에는 이미 ‘다시 시도해주세요’가 있으므로 ‘재시도 안내가 전혀 없다’는 표현은 수정해야 한다. 부족한 부분은 부분 삭제 사실·진행 상태·복구 가능한 후속 동작의 안내다. |
| V-ANON-MIGRATE | 검증 필요 항목으로 수용. 현재 src에서 signInAnonymously 호출은 없지만 잔존 익명 세션과 공급자 토큰을 함께 가진 경우의 서버 이전 경로는 존재한다. 현재 도달성·실제 잔존 세션·배포 코드 일치 확인 전 확정 사용자 간 노출로 등급 부여하지 않는다. |
| 계정 연결·과거 회귀 | 수용. Google/Apple link 성공·충돌·취소 시 UID 및 데이터 소유권을 확인한다. `9478446`, `55510a3`, `41c5d92`는 보안/인증 수정 이력의 증거이며 운영 침해 사고 세 건의 증거로 표현하면 안 된다. |

## 실행 순서

| 단계 | 작업 | 완료 조건 |
|---|---|---|
| 1. 좁은 추가 검증 | 잔존 익명 사용자/인증 설정을 최소 정보로 읽기 확인, 익명→소셜 이전과 link 충돌 코드 경로 격리 재현, 과거 세 커밋의 보호 로직 회귀 목록 작성 | **읽기 전용 범위 완료.** [1단계 인증·익명 이전 추가 검증](STEP_1_AUTH_VERIFICATION.md) 참조. 실계정 E2E는 별도 비운영 Firebase 프로젝트가 필요 |
| 2. 첫 수정 묶음 — 개인정보 경계 | QA-02 UID별 로컬 저장·메모리 초기화·소유자 불명 기존 캐시 처리. 익명 이전은 단계 1 결과에 따라 포함 | **QA-02 로컬 수정·Node 회귀·Chrome 두 탭 fixture·Firebase 에뮬레이터 A↔B 전환 통과.** 첫 에뮬레이터 검사에서 다른 탭의 이전 사용자 표시를 추가 발견·수정. [2단계 QA-02 수정](STEP_2_QA_02_FIX.md) 참조. 실제 소셜 공급자·모바일/PWA·sync 실패 E2E와 배포는 미수행 |
| 3. 둘째 수정 묶음 — 기록 보존 | QA-03·04·05·06·07·21: 중복 방지, 실패 표시/재시도, 초안 보호, AI 작업 버전·중단 검사 | **로컬 수정·격리 회귀·Firebase 에뮬레이터 PC E2E 통과.** 중복 저장, AI 응답 역전, 식단 미분석·분석 중·실패 복원, browser back, 프로필 timeout, 운동 AI 탭 종료 후 재시도를 확인. [3단계 기록 보존 수정](STEP_3_RECORD_PRESERVATION_FIX.md) 참조. 실기기 back/swipe와 실제 폰 네트워크 E2E, 운영 배포는 미수행 |
| 4. 운영 핵심 기능 | QA-01 Gemini 키를 서버에서 관리하고 사용자별 인증·사용량 제한, 기존 키 처리. QA-08 안전한 탈퇴 및 QA-09 Apple 설정/출시 지원 범위 결정 | **운영 배포·전용 계정 E2E 완료.** 인증 AI와 탈퇴 핵심 삭제는 통과했다. QA-22 서버 메타데이터 잔존 수정, 한도 모니터링이 남음. [9단계](STEP_9_PRODUCTION_DEPLOYMENT.md), [10단계](STEP_10_PRODUCTION_ACCOUNT_E2E.md) |
| 5. 나머지 품질과 출시 판정 | P2/P3 수정·전용 계정 정상 여정·실기기 키보드·오프라인·PWA 업데이트·백업 복원 | **진행 중.** Google 전용 계정 정상 여정과 탈퇴까지 통과했다. **남음**: QA-22, Kakao·Naver 실계정, 실기기 키보드·설치형 PWA. 빌드 성공만으로 출시 통과 처리하지 않음 |

QA-01의 공개 키 폐기와 서버 이전은 완료됐다. 이제 새 키 사용량·비용 알림과 사용자별 한도가 실제 트래픽에서 맞는지 확인한다.

> 2026-09-11 9단계 기준: QA-01은 운영 키 폐기·교체와 프록시 배포까지 완료됐다. 인증된 운영 호출 1회와 비용 모니터링은 별도 출시 게이트다.

## 지금 이어서 할 일

개발자나 다음 모델은 새 코드 수정보다 남은 실제 환경 검증을 먼저 수행한다.

1. QA-22를 수정해 탈퇴 성공 뒤 `aiUsage`와 식별 가능한 완료 상태가 남지 않도록 하고 전용 계정으로 재검증한다.
2. Kakao·Naver 계정으로 최초 로그인, 취소, 재로그인, 계정 충돌 시 데이터 소유권을 확인한다.
3. iPhone과 Android에서 설치형 PWA 업데이트, 오프라인 초안 복원, 키보드·safe area를 확인한다.
4. AI 사용량과 비용 알림을 확인하고 초기 한도 10분 30회·하루 200회가 적절한지 결정한다.
5. Cloud Functions Node.js 20 종료일 전에 지원 런타임으로 올리고 전체 함수 회귀를 실행한다.

실계정이나 실기기가 없으면 해당 항목을 버그로 단정하지 말고 검증 필요 상태로 유지한다. 기존 사용자 기록을 대신 사용하거나 탈퇴시키지 않는다.
