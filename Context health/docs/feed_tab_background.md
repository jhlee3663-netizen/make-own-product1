# 피드 탭을 만들게 된 배경

> 하단 내비의 **코치** 탭을 **피드** 탭으로 바꾸기로 한 이유와 방향. 2026-10-15 논의 정리.

## 1. 출발점: 코치 탭은 쓸 이유가 없다

코치 탭(Gemini 대화방 5개)은 디자인보다 **역할**이 문제였다.

- **방 5개는 이름만 다르다.** 스트렝스 멘토·덤벨 마스터·식단 관리사·스트레칭 코치·루틴 설계사는 같은 모델에 지시문 한두 줄만 다르다. 사용자는 묻기 전에 "누구에게 물을지"부터 골라야 하고, 대화는 방마다 흩어진다.
- **내 기록을 거의 모른다.** 최근 운동 5개의 제목·총 볼륨, 식단 5개의 칼로리 정도만 넘어간다. 답이 일반론이 된다.
- **디자인이 따로 논다.** 분홍(#FF5D8F)·파스텔·이모지 아바타로, 지금 홈(보라 #7171FF·흰 카드·그라데이션 선)과 다른 앱처럼 보인다.

그리고 결정적으로, **앱 안의 AI 대화는 경쟁력이 없다** (개발자 본인의 사용 경험):

1. Claude를 이미 구독하고 있으면, 앱에서 저가 API로 더 낮은 수준의 답을 들을 이유가 없다. AI를 구독하는 사용자도 같은 생각을 할 것이다.
2. 정확도가 Claude보다 떨어지는데, 그렇다고 더 편하지도 않다.
3. Claude 커넥터(읽기·쓰기)가 생겨서, 쓰던 AI가 내 기록을 직접 본다. 앱 안 코치가 더더욱 필요 없다.

→ **AI는 기록을 정리하는 데만 쓰고(운동 메모 정리, 음식 성분 추정), 대화는 각자 쓰는 AI에 맡긴다.**

단, 하단 내비는 디자인상 **입력 버튼을 빼고 4칸**이고 홈·분석·마이는 모두 필요하다. 코치 자리를 다른 것으로 **채워야** 한다.

## 2. 채울 것을 찾은 과정

기능을 먼저 떠올리지 않고, **운동·식단 관리하면서 이 앱 말고 실제로 무엇을 하는지**에서 출발했다.

### 사용자 관찰 (개발자 본인과 친구들)

| 관찰 | 의미 |
|---|---|
| 운동은 **지인에게 직접 배우거나 유튜브 영상**으로 배운다 | 운동 코칭은 앱이 끼어들 자리가 아니다 |
| Claude에게 묻는 건 **대부분 식단**, 운동은 거의 안 묻는다 | 식단 질문은 입력 정확도 문제에 가깝다 (공용 음식 사전·AI 추정으로 대응 중) |
| 친구끼리 카톡으로 "가슴 조지고 온다", "오늘 러닝 개조졌다" | 운동 인증은 하지만, **데이터가 아니라 일상 수다** |
| 더 자랑하고 싶으면 인스타 스토리 | 올리는 건 **몸 사진**(근육, 펌핑)이지 무엇을 했는지가 아니다 |
| **운동 잘하는 친구 한 명이 적어 둔 루틴을 따라간다** | 가장 날카로운 지점 |

### 검토했다가 내려놓은 안

| 안 | 내려놓은 이유 |
|---|---|
| 앱 안 AI 코치 개선 (코치 하나로 합치기, 기록 더 넘기기, 먼저 말 걸기) | 위 1장의 세 가지 이유. 아무리 고쳐도 구독 AI를 못 이긴다 |
| 다음 운동 준비 (지난번 무게 다시 보기) | 필요하지만 탭까지는 아니다. 운동 메모 화면 안에서 풀 일 |
| 식단 판단 (남은 칼로리로 뭘 먹을지) | 필요하지만 지금 기능과 크게 다르지 않다. 식단 화면 안에서 풀 일 |
| 눈바디(몸 사진) 타임라인 | 실패 위험은 낮지만, 사진을 꾸준히 찍는 사람에게만 의미 |
| 기록 공유 카드 (인스타 스토리용 이미지) | 인스타에는 몸 사진을 올리지 운동 데이터를 올리지 않는다 |
| 친구끼리 기록 보기만 | 흥미롭지만 "남들 다 있는" 커뮤니티 기능. 그 자체로는 뾰족하지 않다 |

### 조사한 것

- **효과가 있었다**
  - Strava: 칭찬(kudos)을 받은 러너가 실제로 더 자주, 더 많이 뛰었다는 연구가 있다. 사람들은 칭찬을 주고받는 친구를 닮아 간다.
  - Hevy(웨이트 기록 앱): 광고 없이 1천만 명 넘게 모았다. 서로 팔로우하는 구조가 다시 돌아오게 만든 핵심으로 꼽힌다.
  - 동기 부여 효과는 **아는 사람 2–5명**일 때 가장 크다는 정리가 여럿 있다. 대부분 업계 블로그라서 근거는 약하다.
- **실패했다**: MyFitnessPal은 2024년 6월 친구 소식 피드를 없앴다. 식단은 남에게 보이고 싶은 기록이 아니어서 그랬을 것으로 본다 (해석). → 친구에게는 **운동만 기본 공개**.
- **국내**
  - 오운완: 모임 단위로 인증 사진을 올리고 순위를 매긴다.
  - 플랜핏: 루틴 추천에 SNS 커뮤니티를 붙였다.
  - 번핏: 기록·과부하 분석이 중심이고, 공유는 곁가지다.
  - 핏프: 식단·운동·신체 기록을 올리는 커뮤니티다.
  - **커뮤니티 자체는 이미 있다.**
- **한계**: 효과 수치는 대부분 러닝·걸음 수 데이터라서 웨이트에 그대로 맞는다는 보장이 없다. 국내 앱의 실제 사용 지표는 찾지 못했다.

## 3. 뾰족한 페인포인트

> **"잘하는 사람의 루틴을 보고 바로 따라 하고 싶은데, 그게 카톡 텍스트·유튜브 영상 속에 흩어져 있어서 헬스장에서 쓰기 어렵다."**

구체적으로 (일부는 추측, 확인 필요):

1. **친구 루틴**: 카톡으로 "루틴 좀 줘" → 텍스트·캡처로 받음 → 헬스장에서 카톡을 다시 찾아 올려 보며 따라 함 → 무게는 친구 기준이라 알아서 맞춰야 함 → 친구는 내가 했는지 모름.
2. **유튜브 루틴**: 영상을 보고 헬스장에 가면 종목·세트·순서가 기억나지 않음 → 영상을 다시 돌려 보거나 대충 함.
3. **친구가 오늘 운동했는지**는 카톡 수다로만 앎. 기록은 이미 앱에 있는데 따로 말해야 함.

공통점은 **보는 것과 하는 것 사이가 끊겨 있다**는 것이다. 다른 앱들의 피드는 "보고 끝"이다.

## 4. 솔루션: 피드 탭

인스타 홈처럼 생긴 탭. 위에는 친구, 아래는 따라 할 수 있는 루틴과 식단.

| 영역 | 내용 | 푸는 문제 |
|---|---|---|
| **스토리 줄** | 오늘 운동한 친구. 누르면 그날 기록이 한 장으로 나온다 (부위·볼륨·종목·PR·한 줄 메모). 박수·한마디·가져오기 | 3 — 기록하면 인증이 끝난다 |
| **유튜브 가져오기** | 링크를 붙여넣으면 AI가 영상에서 종목·세트·영상 시간·팁을 뽑고, 무게는 내 기록 기준으로 맞춘다 | 2 |
| **카드 피드** | 큐레이션 루틴·식단 / 유튜브에서 가져온 루틴 / 친구 루틴·기록 | 1, 2 |
| **모든 카드에 "내 메모로 가져오기"** | 세트·횟수는 그대로, 무게만 나에게 맞춤 (내 지난번 무게 → 비율 추정 → 직접 입력). 식단은 끼니별로 | **핵심 차별점: 보고 바로 해 본다** |
| **프로필** | 친구의 기록·루틴·최고 기록. 루틴과 최고 기록은 기록에서 자동으로 만들고, 루틴은 본인이 확인해야 공개 | 1 |

### 지키는 원칙

- **커뮤니티가 아니라 아는 사람끼리.** 친구는 초대 링크 또는 아이디로만 맺는다. 친구가 아니면 기록이 안 보인다. 모르는 사람이 이름으로 나를 찾을 수 없다.
- **운동만 기본 공개.** 식단·체중은 본인이 켤 때만 보이고, 켜도 숫자만 보인다.
- **친구가 없어도 쓸모가 있다.** 큐레이션과 유튜브 가져오기만으로도 탭이 비지 않는다. 사람을 모으기 어려운 1인 개발에서 중요하다.
- **AI는 정리만 한다.** 유튜브 영상 정리, 기록 정리. 대화하는 코치는 없다.
- **실존 인물의 프로필을 만들지 않는다.** 유튜버는 "유튜브 채널" 페이지로만 보여 주고 밖으로 연결한다.
- **AI 대화가 필요하면 각자 쓰는 AI로 넘긴다** (커넥터, 카드 복사).

## 5. 향후 방향

| 단계 | 넣는 것 | 확인할 것 |
|---|---|---|
| **1** | 코치 제거 · 피드 탭 (큐레이션 + 유튜브 가져오기 + 내 저장 루틴) · 가져오기 · 홈의 코치 카드 정리 | 사람들이 정말 "가져오기"를 쓰나 |
| **2** | 프로필·편집·아이디 · 검색 · 초대 링크 · 친구 요청 · 스토리 · 박수 · 공개 범위 · 루틴 초안·최고 기록 자동 | 친구를 초대하나, 스토리를 보나 |
| **3** | 댓글 · 알림 목록·종 · 폰 알림 · 채널 페이지·팔로우 · 피드에 올리기 · 차단 | |
| **나중** | 유튜버 새 영상 자동 정리 (비용·유튜브 정책 확인 뒤) · PT 트레이너가 회원에게 루틴 주고 기록 확인 (추측, 확인 필요) | |

1단계에는 사람 사이의 관계가 없다. 보안 규칙·개인정보 부담이 거의 없이 핵심 가설("보고 바로 해 본다")을 먼저 확인할 수 있다.

## 6. 위험과 열린 질문

**위험**
- **콘텐츠 운영**: 큐레이션은 매주 새 글이 있어야 살아 있다. 혼자 계속하기 가장 어려운 부분이다. 유튜브 가져오기로 사용자가 채우는 비중을 늘려 줄인다.
- **규모**: 2–3단계까지 가면 화면이 많아진다 (프로필, 검색, 알림, 친구 관리…). 단계마다 확인하고 다음으로 간다.
- **보안**: 친구일 때만 서로 기록을 읽는 Firestore 규칙. 가장 조심해서 만들 곳이다.
- **비용**: 유튜브 영상 정리는 Gemini 비용이 영상 길이에 비례한다. 같은 영상은 한 번만 정리하고 결과를 재사용한다. 길이·횟수에 한도를 둔다.
- **저작권·초상**: 실존 인물 이름·사진을 쓰려면 허락이 필요하다. 루틴은 정리하고 출처 링크를 단다.
- **폰 알림**: 아이폰은 홈 화면에 추가한 사용자만 받는다.

**사용해 보며 확인할 것**
- 친구 루틴을 실제로 어떻게 받아 쓰는지 (위 3장의 추측이 맞는지)
- 유튜브에서 루틴을 가져오는 일이 실제로 생기는지
- 친구들이 앱을 깔고 기록할지

정해야 할 세부 항목(피드 순서, 친구 한도, 영상 길이 한도 등)은 `docs/ia_feed_social.md`의 "정할 것"에 있다.
