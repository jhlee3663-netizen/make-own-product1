## 사용자 요청과 작업 원칙

사용자는 공개 서비스의 AI를 운동·식단 이외의 용도로 사용하거나 요청을 변조해 악용할 수 있는지 확인했고, 대응 구현을 요청했다. 가장 중요한 조건은 다른 기능을 변형하거나 고장 내지 않는 것이었다.

- 변경 전부터 수정 중인 파일이 많았다. 기존 수정사항을 보존했다.
- 이번 작업의 운영 배포는 `aiGenerate` 함수 하나로 한정했다.
- 웹 Hosting, 네이티브 앱, 다른 서버 함수, Firestore 규칙·인덱스는 배포하지 않았다.
- 커밋·푸시는 하지 않았다. 새 파일 일부는 아직 untracked이므로 변경을 보관할 때 빠뜨리지 않는다.

## 확인했던 문제

이전 `functions/index.js`의 AI 프록시는 인증·사용자별 횟수·모델·입력 크기를 검사했지만, 클라이언트의 `contents`, `systemInstruction`, `generationConfig`를 Gemini에 그대로 전달했다. 따라서 로그인 사용자가 AI 역할과 출력 설정을 바꿀 수 있었고, 서버에 기능별 범위 제한이나 전체 사용량 상한이 없었다.

운영의 비로그인 요청은 변경 전에도 401이었다. 실제 악용 발생 여부나 사용자 호출 이력을 조사한 것은 아니다.

### 기존 앱과의 호환 방식

클라이언트 API를 전면 교체하지 않았다. 기존 설치 앱의 요청 형식을 서버에서 식별하는 호환 어댑터를 넣었다.

지원 기능은 운동 메모 정리(툴바·저장 후 백그라운드·홈 재시도), 세트 추천, 부위별 루틴, 운동 한줄평, 음식 분리, 영양 추정, 주간 리포트·상태, 코치 상담 6개 방이다.

- 기능별 기존 문구에서 사용자 데이터만 추출하고 서버가 소유한 지시문으로 요청을 다시 구성한다.
- 코치는 알려진 역할의 첫 문구로 방을 식별한다. 클라이언트 시스템 프롬프트에서는 프로필·최근 기록 구간만 **신뢰하지 않는 입력 데이터**로 보관한다. 클라이언트의 참고 자료와 후속 역할 지시는 버린다.
- `generationConfig`는 서버 설정으로 대체한다. 후보는 1개, 모델은 기존 `gemini-3.6-flash`로 고정한다.
- 텍스트 이외의 파일·도구 호출 등의 입력은 받지 않는다. 익명 인증 계정도 거절한다.
- 새 화면을 만들거나 프롬프트의 식별 문구를 바꾸면 **호환 어댑터와 테스트도 함께 수정해야 한다.** 현재 방식은 명시적 task/data API로 완전히 전환한 구조는 아니다.

### 답변 검사와 실패 처리

- JSON 기능은 Gemini 응답 스키마와 서버의 자료형·필드·수치 검증을 함께 사용한다.
- 생성 후 원래 입력 데이터와 답변을 별도 Gemini 검사기에 보내 범위 이탈·위험 내용·지시문 우회를 검사한다.
- 검사 실패나 잘못된 검사 응답에서는 검증하지 않은 답변을 반환하지 않는다.
- 코치의 정책 차단은 기존 Gemini 응답 형태의 짧은 안내로 반환한다. 기록 변환 기능의 정책 차단은 422다.
- 실제 모델 검사 중 여러 음식의 영양 추정이 배열을 반환하는 문제가 발견됐다. 객체 스키마 및 합산 지시를 추가한 후 전체 실제 모델 검사를 재실행해 통과했다.
- **검사도 확률적인 모델이므로 모든 우회를 막는다고 보장할 수 없다.** 정상 요청의 오탐 가능성도 운영에서 관찰해야 한다.
- 정상 요청마다 생성 1회와 검사 1회가 발생한다. 기존 대비 검사 호출 비용·지연이 추가된다. 전체 업스트림 제한은 기존처럼 30초이며, 실제 모델 가상 데이터 사례는 약 2.5–4.5초였다. 긴 대화/기록의 성능까지 검증한 수치는 아니다.

## 사용량 제한과 운영 설정

| 제한 | 사용자별 | 서비스 전체 |
| --- | --- | --- |
| 요청 횟수 | 기존 10분 30회 / 24시간 200회 | UTC 일자별 5,000회 |
| 예약 단위 | 24시간 800만 | UTC 일자별 1억 |
| 동시 실행 | 6개 | 100개 |

예약 단위 계산은 `UTF-8 요청 바이트 × 2 + 최대 출력 토큰 × 8 + 512`이다. **실제 청구 토큰이나 금액의 정확한 상한이 아니다.** 실패한 요청도 예약량을 환불하지 않는다. 실행 슬롯만 종료 시 해제하고, 해제 실패 시 70초 후 만료된다.

문서 경로:

- `aiUsage/{uid}`: 기존 사용자 카운터에 예약 단위·실행 슬롯 필드 추가. 기존 카운터와 호환.
- `aiServiceUsage/global`: 전체 일일 카운터·예약 단위·실행 슬롯.
- `aiServiceUsage/control`: 운영 설정. 문서가 없으면 코드의 기본값을 사용한다.

`control`에 `{ "enabled": false }`를 설정하면 이 AI 경로를 중단한다. `limits` 아래 다음 필드에 양의 정수를 지정하면 기본 상한보다 낮출 수 있다.

```json
{
  "enabled": true,
  "appCheckMode": "monitor",
  "limits": {
    "userWindowRequests": 30,
    "userDayRequests": 200,
    "userDayTokenUnits": 8000000,
    "userConcurrent": 6,
    "globalDayRequests": 5000,
    "globalDayTokenUnits": 100000000,
    "globalConcurrent": 100
  }
}
```

위 JSON은 설명용 예시다. 이 작업에서 운영 control 문서를 생성하거나 설정을 변경한 것은 아니다. 새 서버 전용 경로는 기존 규칙의 기본 거부 대상이므로 규칙 파일은 바꾸지 않았다. 전체 한도는 **`aiGenerate` 경로에 한정**되며, 소셜 큐레이션 등 다른 AI 호출 경로까지 통합한 것이 아니다.

### App Check는 아직 강제하지 않음

기본은 `monitor`다. 토큰이 없거나 잘못됐으면 메타데이터를 기록하며 요청을 계속 처리한다. 네이티브 앱의 attestation 전송이 준비되지 않아 지금 강제하면 정상 사용자가 막힐 수 있기 때문이다.

`appCheckMode: "enforce"`에서는 유효 토큰이 없는 요청이 403이 된다. **웹·네이티브에서 유효 토큰 전송을 검증하기 전에 켜지 않는다.** 웹 토큰 첨부 코드도 이번 Hosting 미배포로 아직 운영 웹에 반영되지 않았다. 로그인 토큰을 이용한 외부 자동 호출 자체가 완전히 차단됐다고 설명하면 안 된다.

## 운영 배포 사실

- 프로젝트: `context-health-3eb84`
- 대상: `functions:aiGenerate`, `us-central1`
- 배포된 revision: **`aigenerate-00006-xiz`**
- API: `https://context-health-3eb84.web.app/api/ai-generate`
- 배포된 `functions/ai/*.js`가 작업 폴더와 동일함을 파일 내용 비교로 확인했다.
- 기존 `functions/index.js`에서 `migrateAnonymousData` 이후의 다른 함수 코드는 작업 시작 직전 사본과 동일함을 확인했다. 작업 전부터 있던 Sentry SDK 지연 로딩 변경도 보존했다.

일반 배포 명령은 로컬 전체 함수 분석 단계에서 10초, 60초 모두 타임아웃됐다. 정확한 개별 모듈 원인을 확정하지는 못했다. 같은 잠금 파일의 의존성을 임시 폴더에 새로 설치한 AI 전용 배포본에서는 함수 분석·배포가 통과했다. 원본 `functions/node_modules`나 의존성 버전은 변경하지 않았다.

재배포가 필요하면 프로젝트 루트에서:

```bash
node scripts/prepare-ai-deploy.mjs
```

출력된 임시 폴더를 확인한 뒤:

```bash
cd "<출력된 임시 폴더>/functions"
npm ci --ignore-scripts --no-audit --no-fund
cd ..
npx -y firebase-tools@latest deploy --only functions:aiGenerate --project context-health-3eb84 --non-interactive
```

임시 배포본은 원본 index에서 CORS 및 AI 연결 부분을 추출하고 AI 모듈·기존 package/lock을 복사한다. 원본 코드의 구조를 바꾸면 추출 스크립트도 점검한다. 전체 함수/Hosting 배포로 범위를 넓히지 않는다. CLI 디버그 로그에는 환경 변수나 비밀값 응답이 포함될 수 있으므로 원문을 공유·커밋하지 않는다.

| 브라우저 화면 | 기존 로그인 세션의 구버전 UI가 표시됨. 캐시/서비스 워커에 의한 구버전으로 판단. 최신 UI 전체 회귀 검증으로 간주하지 않음. 공개 최신 번들의 기능별 요청 식별 문구는 별도 확인. 콘솔을 이용한 운영 검사 시도에서도 성공 결과를 얻지 못했으며, 임시로 연 검사 탭은 닫았음. |

## Claude가 다음에 확인할 사항

1. 우선 위 미검증 항목을 해결한다. 로그인한 운영 경로에서 정상 코칭·운동 정리·식단 분석과 차단 요청을 확인하고, 실제 트랜잭션에서 카운터·실행 슬롯이 올바르게 동작하는지 확인한다. 검증을 위해 IAM·Auth·App Check를 임의로 완화하지 않는다.
2. 최신 UI/설치 앱에서 기존 AI 응답 파싱·추천 적용·메모 보존이 유지되는지 확인한다. 구버전 UI만 보고 최신 화면 검증을 완료 처리하지 않는다.
3. 응답 검사로 인한 오탐·지연·비용을 관찰한다. 긴 기록, 긴 대화, 연속 음식 추정, 대량 메모에서 출력 상한·시간 제한이 정상 사용을 방해하는지도 확인한다.
4. 웹 App Check 첨부/오류 안내는 로컬 변경만 존재하므로 이후 필요한 클라이언트 변경과 함께 검토한다. 네이티브 토큰 전송을 준비하고 검증한 후에만 enforcement를 고려한다.
5. 기능을 추가할 때는 장기적으로 명시적 task/data 요청으로 전환하는 방안을 검토할 수 있다. 현재 호환 어댑터를 바로 제거하면 설치된 구버전 앱이 깨질 수 있다.

## 되돌리기와 기존 작업 보호

이번 AI 모듈과 index의 AI 연결 부분만 이전 구현으로 복구한 뒤 `aiGenerate`만 재배포한다. 사용자별 기존 카운터 필드는 이전 서버와 호환된다. App Check 및 글로벌 예약 필드가 남는 것만으로 이전 서버가 이를 사용하지는 않는다.

**`git reset --hard`나 파일 전체 `git checkout/restore`로 되돌리지 않는다.** 특히 `functions/index.js`에는 작업 전 수정사항이 있었다. 작업 시작 사본 `/tmp/context-health-ai-index-before.js`가 같은 기기에 남아 있을 수 있으나 임시 파일이므로 영구적인 롤백 근거로 의존하지 않는다. Git diff와 이 문서를 기준으로 변경 구간을 구분한다.

현재 상태는 “AI 서버 보안 변경 배포 + 모의/실제 모델 검사 통과 + 운영 통합 검증 일부 미완료”다. “모든 기능 무고장 확인”, “모든 악용 차단”, “App Check 강제 완료”로 보고하면 안 된다.
