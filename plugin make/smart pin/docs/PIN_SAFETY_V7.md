# Smart Pin v7 — 권한 및 복구

## 적용 내용

- 새 핀은 Figma 사용자 ID를 작성자로 기록합니다. 이름은 표시 용도이며 권한은 ID로 판단합니다.
- 작성자와 지정된 공동 편집자만 제목·내용·카테고리·그룹·번호를 수정합니다. 보호 핀은 작성자만 수정합니다.
- 담당자는 상태만 변경합니다. 공동 편집자에게 삭제 권한은 주지 않습니다.
- 일반 삭제는 휴지통 이동입니다. 작성자만 직접 삭제하고, 관리자는 보호되지 않은 핀의 삭제 요청을 사유와 함께 처리할 수 있습니다.
- 작성자/관리자가 복구할 수 있습니다. 영구 삭제와 권한이 있는 항목만 휴지통 비우기는 확인 및 사유 입력이 필요합니다. 보호 핀의 영구 삭제는 작성자만 가능합니다.
- 휴지통은 최소 30일 보관 취지보다 보수적으로, 자동 만료 없이 명시적 영구 삭제까지 보관합니다.
- 삭제 직후 실행 취소, 페이지에서 내 핀만 일괄 삭제 확인, 원래 레이어 복구/새 레이어 연결을 제공합니다.
- 캔버스에서 배지가 사라져도 글을 삭제하지 않습니다. 누가 지웠는지 알 수 없으므로 관찰자를 삭제자로 기록하지 않습니다.
- 의견·수정/삭제 요청·기존 핀 작성자 등록 요청, 공동 편집자·담당자 지정, 소유권 이전, 내용 이력 복원을 제공합니다.
- 관리자는 타인의 원문을 직접 수정하지 않습니다. 필요한 경우 사유를 기록하여 소유권을 이전합니다. 최초 관리자는 팀이 합의한 사람이 명시적으로 등록합니다.
- 관리자 변경 이력과 핀별 변경 이력을 표시합니다. 요청은 파일 내부에 저장되며 이메일 등 외부 알림은 보내지 않습니다.
- 활성/휴지통 핀과 이력의 JSON 내보내기, 백업의 핀을 내 새 핀으로 가져오기를 제공합니다. 가져오기는 기존 ID, 관리자 권한, 소유권, 이력을 덮어쓰지 않습니다.
- 예전 ‘복구’ 상태 버튼은 ‘다시 열기’로 변경했습니다.

## 저장과 기존 파일 전환

기존 전체 배열 덮어쓰기를 새 저장 영역의 변경 불가능한 핀별 수정본으로 교체했습니다. 본문 청크를 저장한 뒤 검증 정보를 기록하므로 중간 실패는 이전 수정본을 손상시키지 않습니다. 메시지 처리는 한 실행 안에서 순차 처리하며 저장 성공 후에만 성공 알림을 냅니다.

오래된 수정본으로 편집하면 충돌을 알립니다. 두 클라이언트가 동시에 만든 분기는 둘 다 기록에 남으며 적용되지 않은 분기는 이력에 표시됩니다. 서버 트랜잭션이나 실시간 다중 사용자 잠금은 아닙니다.

기존 핀은 작성자 미상으로 보존합니다. 사용자가 ‘내 핀 등록 요청’을 남기고 관리자가 확인하거나 관리자가 직접 작성자를 지정합니다. 처음 파일을 연 사람에게 자동 귀속하지 않습니다. 최초 전환 시 v1 데이터는 전환 복구용으로 그대로 남겨두며 v7은 새 영역만 읽고 씁니다. 휴지통 영구 삭제는 v2 본문/이력을 제거하지만 기존 v1 스냅샷, Figma 버전 기록, 이미 내보낸 백업까지 소거하지는 않습니다.

편집 중 마지막 전송 초안은 현재 브라우저 세션에 보관합니다. 충돌/실패 시 카드의 ‘이 세션의 마지막 입력 사본’에서 복사할 수 있습니다. 이는 서버 백업이 아닙니다.

## 설치와 확인

1. 먼저 실제 Figma 파일의 복제본에서 확인합니다.
2. `npm run package:local`로 로컬 설치 파일을 만듭니다. 이 명령은 GitHub에 게시하지 않습니다.
3. Figma 개발 플러그인 가져오기에서 `deploy_figma/manifest.json`을 선택합니다. ZIP을 받았다면 먼저 압축을 풉니다.
4. `manifest.json`, `code.js`, `ui.html`을 함께 교체해야 합니다. 새 사용자 식별 권한과 버전 일치 UI가 포함됩니다.
5. 팀원 모두 v7로 교체합니다. 구버전은 새 권한/휴지통을 모르며 계속 사용하면 배지나 이전 저장 데이터가 달라질 수 있습니다.
6. 헤더의 ‘관리’(톱니) → ‘팀 권한 및 관리자’에서 합의한 관리자를 등록하고, ‘처리할 요청’에서 기존 핀의 작성자 등록 요청을 확인합니다.

배포용 UI는 코드와 함께 묶었습니다. 구버전 코드와 원격 신버전 UI가 섞이는 것을 방지합니다. 기존 웹 뷰어 내보내기는 활성 핀만 전달하며 휴지통·권한·이력은 포함하지 않습니다.

## 검증

- `npm test`: 권한, 위조된 메시지, Dev Mode, 마이그레이션, 충돌 분기, 저장 실패, Unicode 대용량 데이터, 휴지통/복구/영구 삭제, 소유권 이전, 요청 승인, 백업 가져오기 회귀 테스트.
- `npm run typecheck`, `npm run build`: 통과. Figma/DOM 선언 충돌은 `skipLibCheck`로 분리하며 애플리케이션의 strict 타입 검사는 유지합니다.
- `tests/browser.cjs`: 실제 Chrome에서 빌드된 React UI와 모의 Figma API(실제 `code.ts`)를 연결해 다른 사용자 읽기 화면·의견·삭제 요청, 카드 `...`에서 관리 진입 시 핀 재선택 없음, 작성자 편집·상태 변경·휴지통/실행 취소와 삭제 직전 초안 보존, 공동 편집자 자동 저장, 담당자 상태 전용, 작성자 미상 등록 요청과 승인, 최초 관리자 등록, 영구 삭제, 백업 다운로드, 720/360px 가로 넘침을 검증합니다. 스크린샷은 `evidence/`에 있습니다.
- `tests/editor-browser.cjs`: rich text 왕복(기존 `**`/`__`/`*`/`•` 표기), 선택 팝업 서식, bullet 종료(Enter/Backspace), 텍스트 드래그 방지, 편집 중 카드 눌림 효과 없음, 자동 저장(디바운스·핀 전환 시 즉시 저장) 회귀를 검증합니다.
- 두 브라우저 테스트는 `npm run build` 후 `PLAYWRIGHT_PATH=<playwright 또는 playwright-core 경로> node tests/<파일>`로 실행합니다.
- 실제 Figma의 두 계정 동시 실행, Figma Undo/Redo, 실제 대형 파일의 동기화와 설치 권한 표시는 아직 별도 확인이 필요합니다.

## 적용 범위

이 권한은 Smart Pin 내부의 협업 규칙입니다. 파일 편집자가 Figma 캔버스를 직접 조작하거나 별도의 플러그인으로 공유 데이터를 변조하는 것까지 막는 서버 보안은 아닙니다. 악의적인 파일 편집자까지 통제하려면 인증된 서버 저장소와 서버 측 권한 검사가 필요합니다.

수정 이력은 데이터 손실 방지를 위해 자동 정리하지 않습니다. 장기 사용으로 저장 한도에 도달하면 저장 실패를 표시하며 기존 데이터를 유지합니다. 파일별 장기간 실제 용량과 성능은 운영 검증 대상입니다.

## UI 구조 (TDS Mobile 기준)

- 디자인 토큰은 `Toss mobile md/tokens.ts`를 `src/tds.ts`에서 직접 가져와 사용하고, 공통 컴포넌트(Button, ListRow, BottomSheet, Menu, Toast 등)는 `src/tds-ui.tsx`에 있습니다.
- 핀 카드: 접힌 상태에서는 번호·제목·상태·카테고리·작성자·보호 여부만 보여줍니다. 링크 복사, 의견·권한·이력, 휴지통 이동(다른 사람 핀은 삭제 요청)은 카드 우측 `...` 메뉴에 있습니다.
- 편집: 저장하기만 하단 고정 Primary CTA입니다. 상태(진행 전·보류·완료)는 폼 안의 선택 컨트롤로 바꾸며, 권한이 없으면 입력 폼 대신 읽기 화면을 보여줍니다.
- 관리: 헤더의 ‘관리’에서 받은 의견함·휴지통·팀 권한 및 관리자·백업 및 복원을 ListRow로 엽니다. 카드에서 들어가면 해당 핀의 관리 화면으로 바로 이동하며, 확인과 사유 입력은 bottom sheet로 받습니다.
- 성공·실패 알림은 하단 toast로 통일했고, 휴지통 이동 직후 toast에서 실행 취소할 수 있습니다.
- 받은 의견함: 내 핀에 다른 사람이 남긴 의견·수정 요청·삭제 요청이 최신순으로 모입니다. 관리자에게는 작성자 등록 요청과 다른 핀의 삭제 요청도 보입니다. 일반 의견은 ‘확인’ 한 번으로 처리 완료되며(사유 ‘의견 확인’으로 기록), 승인·거절은 사유를 받습니다. 헤더 관리 아이콘 badge와 카드의 ‘의견 N’에 개수가 표시되고, 플러그인이 열려 있는 동안 새 의견이 오면 toast로 알립니다. 외부(메일·메신저) 알림은 없습니다.
- 새로워진 점 안내: v7을 처음 실행한 사용자에게 한 번만 5장짜리 안내를 보여줍니다. 관리 화면의 ‘새로워진 점 다시 보기’로 다시 볼 수 있습니다. 새 파일의 첫 사용자는 기존 온보딩만 봅니다.
- 사용자별 UI 설정(안내 확인 여부, 언어)은 `figma.clientStorage`에 저장합니다. 플러그인 UI iframe에서는 localStorage를 쓸 수 없기 때문이며, 핀 데이터나 권한과는 무관합니다.
- 캔버스 배지 점검: 플러그인은 5초마다 현재 페이지의 배지를 **읽기만** 합니다. 같은 핀의 복제된 배지와, 대상 레이어 기준 위치에서 벗어난(또는 프레임 안으로 끌려 들어간) 배지를 찾아 카드와 목록 상단에 알려줍니다. ‘복사본 정리’와 ‘위치 맞추기’는 사용자가 눌렀을 때만 실행되어 다른 사람의 실행 취소 기록에 끼어들지 않습니다. 원래 배지가 지워지고 복사본만 남았다면 정리 시 그 복사본을 이 핀의 배지로 연결합니다. 진단 결과는 화면 전송용이며 저장하지 않습니다. 정리와 개별 위치 맞추기는 해당 핀을 수정할 수 있는 사용자만 할 수 있습니다.
